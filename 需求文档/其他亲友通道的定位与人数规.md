# 其他亲友通道的定位与人数规


## C｜其他亲友通道的定位与人数规则

### C0｜为什么“其他亲友”不是一个人

B 端身份入口仍然固定为 8 个：

- 新郎（单人）

- 新娘（单人）

- 新郎父亲（单人）

- 新郎母亲（单人）

- 新娘父亲（单人）

- 新娘母亲（单人）

- 新郎其他亲友（多人通道）

- 新娘其他亲友（多人通道）

其中 **“新郎其他亲友 / 新娘其他亲友”不是某一个固定身份的人**，而是 **“多人可重复进入的采访通道”**，用于承载除新人和双方父母之外的所有参与者。

结论：

- **入口类型仍是 8 个（固定不变）**

- **参与采访的人数不固定（其他亲友为多人通道）**


### C0.1｜其他亲友通道支持的参与者范围

“其他亲友”可覆盖但不限于：

- **长辈类**：爷爷奶奶、外公外婆、叔伯姑姨舅、长辈亲属、师长等

- **同辈类**：兄弟姐妹、堂表亲、同学同事、伴郎伴娘、好友、闺蜜、兄弟团等

一句话：**“其他亲友”是多参与者通道，不是单人身份。**


### C0.2｜多人进入时的最小产品规则（本期建议写死）

#### 规则 1：每次进入 = 一个独立“亲友席位”

- 任意人从“其他亲友”入口开始采访，都视为占用一个亲友席位。

- 每个席位完成后，会生成一份对应的采访沉淀（文章/胶囊）。

- 该份内容在后台列表中，以参与者填写的 **“称呼/姓名”** 作为显示名（未填写则用系统默认名）。


目的：保证“多人可用”的同时，内容可追溯、可区分、可管理。

#### 规则 2：**亲友人数上限**

- **每个项目**：

- **新郎侧**最多允许 10 位“其他亲友”参与采访

- **新娘侧**最多允许 10 位“其他亲友”参与采访

- 达到上限后：

- 参与者端会提示：“本场亲友采访名额已满，请联系主持人。”

- 主持人端可通过重置某位亲友的内容来**释放名额**（重置后名额回收）。

#### 规则 3：进入其他亲友后，AI 必须先问一句“你是谁”（最小判定）

- 进入采访后第一问固定为：

- “你和新人是什么关系？（例如：长辈 / 朋友同事 / 兄弟姐妹 / 其他）”

- 这一步的目的：

- 不是做复杂分类

- 只为后续“内容归档/展示口径”提供必要依据（尤其是你提到的 C1/C2 通用表）

#### 规则 4：不做“占用锁定”，避免卡住多人使用

- 父母/新人属于“单人通道”，可做强约束（一个身份只对应一条通道）。

- **其他亲友不做“只允许一人占用”**，否则会出现：

- 某人误进/中途退出，导致后续亲友无法继续

- 主持人需要频繁手动解除占用，流程变复杂

因此，本期口径明确为：
**其他亲友 = 多人可连续提交，不做占用锁。**

#### 规则 5：无法判定关系时的兜底

若参与者不愿回答/信息不足/系统判定失败：

- 仍允许继续采访

- 内容进入“其他亲友”列表

- 在后台显示名上标记为：**“亲友（未说明关系）”**（用于主持人后续人工识别）


本期不强制把“判定失败”引入复杂的“兜底归档固定名”，避免逻辑分叉过多；你那套 C1/C2 表仍可在后续版本做更细。


### C1 / C2 通用表的使用方式（保持不变，但写法更清晰）

- 当 AI 已拿到“关系类型”信息后：

- **偏长辈** → 使用 C1 表对应的沉淀规则

- **偏朋友/同辈** → 使用 C2 表对应的沉淀规则

- 具体映射表不在本节展开，引用《B→C 沉淀规则》独立文档即可。
