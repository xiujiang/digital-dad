# 统一后台系统信息架构与菜单规则





**目标：** 在“一套后台”的前提下，把**菜单结构、可见性规则、数据范围口径**写死，保证开发实现时不会再出现“像两套后台”的割裂感。


### 1）统一后台的登录与身份识别

**1.1 账号体系**

- 系统只有一种登录入口（同一登录页、同一域名/系统）。

- 登录成功后，由后端返回当前账号的 **角色**：

- 角色=主持人

- 角色=平台管理员

**1.2 角色决定可见菜单与可操作范围**

- 前端：按角色渲染菜单与页面入口（不展示无权限入口）。

- 后端：按角色强鉴权（即使手动拼 URL 也访问不到越权数据）。


### 2）左侧导航：统一菜单树


统一后台只有一套菜单树，但不同角色看到的菜单项不同。
**原则：** “同名模块同一套页面”，只是数据范围与操作按钮按角色开关。

#### 2.1 主持人可见菜单（主持人视角）

1. 项目管理

1. 生成日志（主持人侧的“生成记录 + 配额扣减对账”）

1. 我的资料（含：会员/配额信息、联系方式展示开关、基础资料维护）

1. 退出登录


主持人不应看到：主持人管理、全局项目管理、会话日志、提示词中心、录音存证、审计日志等平台治理能力入口。

#### 2.2 平台管理员可见菜单（平台管理员视角）

1. 系统总览（仪表盘）

1. 主持人管理

1. 项目管理

1. 采访对象

1. 生成物

1. 会话日志

1. 提示词中心

1. 录音存证

1. 审计日志

1. 退出登录


平台管理员需要看到全站数据与治理工具，用于运营、排障、审计与版本发布。


### 3）同名模块“同一页面”的复用策略（关键）

为避免“像两套后台”的割裂，统一后台遵循以下规则：

#### 3.1 同名同入口同页面

- 「项目管理」：主持人/管理员进入的是同一页面组件与路由

- 「生成日志」：主持人/管理员进入的是同一页面组件与路由（但字段与筛选项权限不同）

#### 3.2 通过“数据范围”+“操作权限”实现差异

- **主持人数据范围**：仅限 `host_id = 当前账号` 绑定的数据

- **平台管理员数据范围**：全平台数据（可按 host_id/project_id 等筛选）


### 4）数据域与边界口径（必须写死）


这里是你强调的核心：**C 端资产不可被 B 端改写**，平台侧只能看到“主持人业务需要看到的映射结果”，不能反向污染 C 端。

#### 4.1 三层数据域（概念边界）

1. **C 端用户资产域**（用户数字资产）

- 由采访产生的“沉淀内容”属于 C 端资产域

- 资产归属：每个用户自己

- **不可被任何 B 端/后台编辑改写**（包括主持人端、管理员端）

1. **主持人业务交付域**（B 端可见内容）

- 用于婚礼项目交付的可消费内容：项目摘要、采访进度、生成物交付状态等

- 本质是从 C 端资产域“引用/映射/聚合”而来，或是系统生成的交付物

- 主持人可见，但只能做“交付相关动作”（如触发生成、下载、分享），不能改写 C 端资产

1. **平台治理域**（管理员工具域）

- 全平台指标、成本、日志、审计、提示词版本、录音存证等

- 管理员可见可管，但同样**不可修改 C 端资产内容本体**

#### 4.2 单向同步规则（你要求的硬约束）

- **C → B：允许**

- C 端采访内容沉淀完成后，B 端可提示“内容已更新/可生成/可交付”

- **B → C：禁止**

- B 端任何修改（提示词版本变更、生成物重跑、后台操作）不得改写 C 端原始沉淀内容

- 例外仅限“系统级纠错”且必须留痕（但首期建议不做，避免复杂度爆炸）


### 5）筛选与“全部项目”的口径

#### 5.1 主持人视角不存在“全平台全部项目”

- 主持人页面里可以有“全部项目”，但含义是：**该主持人名下的全部项目**（仅自己范围内的汇总）

- 也可以提供“按项目切换 / 全部项目”筛选，但“全部项目”仍然是 **我的全部项目**

#### 5.2 平台管理员视角的“全部项目”才是全平台

- 管理员页面的“全部项目”=全平台总账/总览

- 同一控件文案一致，但数据范围因角色不同而不同：

- 主持人：全部项目=我的全部项目

- 管理员：全部项目=全平台全部项目


**开发提示：** 这是权限过滤的经典场景：前端文案不必区分两套后台，但后端必须按角色过滤数据。


### 6）中文规范（全系统统一）

- 所有菜单、字段、状态、按钮、提示语：**全部中文**

- 不出现任何英文术语（包括模型名、tokens 等）：

- “模型”可写为：模型版本/引擎版本（展示给管理员也用中文）

- “tokens”可写为：消耗量/算力消耗/调用量（具体口径后续在日志页再定）


### 7）本页输出结论（供你放在文档页尾）

- 统一后台只有一个入口与一套菜单体系

- 通过角色（主持人/平台管理员）控制：

- 菜单可见性

- 数据范围（我的 vs 全平台）

- 操作权限（能否管理他人/能否发布提示词/能否看审计等）

- 数据边界硬约束：**C → B 单向同步**，**B 端不可影响 C 端用户数字资产**
