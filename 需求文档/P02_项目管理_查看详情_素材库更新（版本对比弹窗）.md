# P02_项目管理_查看详情_素材库更新（版本对比弹窗）



## 1）弹窗定位

- **端：**B 端（主持人管理后台）

- **目标：**当 C 端参与者对“某一素材卡片”产生了更新版本时，主持人在后台可查看“当前版本 vs 新版本”的差异，并决定是否采用新版本。

- **入口：**项目详情页 → 素材库卡片出现「更新提示」→ 点击「查看更新」

- **出口：**

- 点击「取消」关闭弹窗，不做任何变更

- 点击「采用新版本」关闭弹窗，并以新版本替换当前版本


## **2.0 版本产生规则（C端｜“什么时候算新版本”）**


### **2.0.1 基本原则（首期写死）**


- 不是每次保存都产生新版本。

- 只有当参与者在 C 端“明确提交更新并成功”时，才产生新版本（版本号 +1）。

- 编辑中 / 自动保存 / 草稿状态不会产生新版本，也不会触发 B 端更新提示。



### **2.0.2 会产生新版本的操作（触发 v+1）**


满足以下任一行为，产生新版本并触发 B 端出现「更新提示」：


1）继续补充（追加）后提交成功


- 参与者进入某身份通道，选择“继续补充”，在原内容基础上补充信息，点击提交成功 → 生成 v+1。

2）覆盖重填确认后提交成功（高风险）


- 参与者进入某身份通道，选择“覆盖重填”，确认风险提示后重新填写，提交成功 → 生成 v+1。

3）对已沉淀内容进行编辑并提交成功


- 参与者对已生成/已沉淀的内容进行修改，点击提交成功 → 生成 v+1。


说明：以上行为的共同点是“用户明确提交 + 服务端保存成功”。




### **2.0.3 不产生新版本的操作（只算草稿/临时态）**


以下情况不产生新版本，也不触发 B 端更新提示：


- 自动保存 / 离开页面的草稿保存

- 未点击提交就退出页面

- 仅查看、仅复制、仅导出

- B 端任何操作（查看/采用/生成/导出/重置）均不产生 C 端新版本（B 端只读引用）



### **2.0.4 版本号与展示口径（给弹窗用）**


- 初始版本：v1.0（首次提交成功形成的定稿）

- 后续版本：每次提交成功 v+1（v2.0、v3.0……）

- 弹窗「修改人」显示口径（用于 3.2 更新提示条）：

- 优先：C 端填写的「称呼/姓名」

- 其次：身份名称（如“新郎”“男方其他亲友-3”）



### **2.0.5 为什么这么做（产品口径，给工程对齐）**


- 避免“版本爆炸”（每次草稿都一个版本）

- 避免“未完成内容误同步到 B 端”（B 端看到的必须是参与者确认提交过的内容）

- 保证“C 端是源数据，B 端是只读镜像”的数据边界清晰


## 2）触发条件

当某素材通道存在 **新版本（v2.0、v3.0…）** 且后台仍保留旧版本（v1.0）时：

- 在素材卡片区域显示「更新提示」组件

- 点击「查看更新」打开本弹窗


## 3）页面信息结构（按截图）

### 3.1 标题区

- 标题：**版本对比 - {显示名}**

- `{显示名}`：当前素材所属人员的展示名（如：小明 / 新郎 / 大伟等）

- 关闭按钮：右上角「×」

### 3.2 更新提示条（橙色提示块）

展示新版本概览：

- 文案：**C端已产生新版本：v2.0**

- 更新时间：`YYYY-MM-DD HH:mm`

- 修改人：`参与者显示名/身份`（如：新郎A）


目的：让主持人明确“确实是 C 端更新导致的版本变化”，并知道时间与来源。

### 3.3 版本对比区（左右两栏）

两栏并排展示，顶部各自带版本标识：

**左栏：当前版本（v1.0）**

- 内容区域：展示当前版本的“内容摘要/正文片段”（与素材卡片内展示内容一致）

**右栏：新版本（v2.0）**

- 内容区域：展示新版本的“更新内容/正文片段”

- 若新版本较长：内容区域可滚动


注：此弹窗以“可读性”为第一优先，不要求技术级 diff；用户能看懂两段内容差异即可。

### 3.4 风险提示区（红色提示条）

固定提示（必须清晰、强提醒）：

- 文案：**注意：采用新版本后，当前版本内容将被新版本替换。请确认是否继续。**

### 3.5 底部操作区

- 左侧按钮：**取消**

- 右侧主按钮：**采用新版本**（带刷新/替换含义图标）


## 4）交互规则

### 4.1 关闭/取消

- 点击右上角「×」或「取消」：

- 直接关闭弹窗

- 当前版本不变

- 更新提示仍保留（便于下次再处理）

### 4.2 采用新版本（核心）

- 点击「采用新版本」后：

- 将该素材卡片的**展示与后续使用版本**切换为新版本（例如 v2.0）

- 弹窗关闭

- 该素材卡片的版本标识更新为 v2.0

- 「更新提示」消失（因为已同步到最新）


口径：**“采用”=替换当前版本作为有效版本**，后续 AI 生成将以该有效版本为准（若该素材参与生成）。


## 5）异常与边界（最少必写）

- **新版本不存在/已被处理：**提示“更新已处理或不存在”，关闭弹窗

- **网络异常：**提示“网络不稳定，请稍后重试”

- **并发冲突（同一时间主持人已采用）：**提示“版本已更新为最新”，刷新卡片状态


## 6）与生成内容的关系说明（写给主持人的一句话）

- 该弹窗只影响**素材库该条素材**的有效版本；

- **后续点击「AI 生成/重新生成」时，会使用当前有效版本的素材**。


## 7）数据权属与同步规则

### 7.1 主持人后台“可见内容”的范围（只读）

- **主持人后台有且只能看到：**本次婚礼采访中，参与者在 C 端最终沉淀的内容（即“写入 C 端个人数字资产”的那 4 份内容/文件）。

- 主持人后台展示的“素材库内容 / 版本对比 / 更新提示”，本质上是对 **C 端已沉淀内容的只读镜像**（Read-only View），用于本次婚礼交付与生成。

- 主持人后台展示的内容仅来自参与者已提交成功的版本；草稿与未提交内容不在 B 端可见范围内。


结论：B 端没有“编辑 C 端内容”的入口与权限，只能查看与选择使用哪个版本作为“本次交付引用版本”。


### 7.2 同步方向（单向：C → B）

- **允许的影响方向：**C 端内容更新 → 触发 B 端出现「已更新」提示，并在版本对比弹窗中展示新版本。

- **不允许的影响方向：**B 端任何操作（查看/采用/生成/导出/重置）**不得反向写入或覆盖 C 端内容**。


结论：同步是单向的——**C 端是源数据（Source of Truth），B 端只是引用（Reference）**。


### 7.3 “采用新版本”的真实含义（避免误解）

- 在 B 端点击「采用新版本」仅表示：

- **本次婚礼项目在 B 端的“引用版本”切换到最新版本**；

- 用于后续 **AI 生成 / 导出 / 交付**时优先使用该版本。

- **它不等价于**“修改/替换 C 端个人资产内容”，也**不会**改变 C 端用户侧的任何文本、版本与记录。


### 7.4 为什么必须这样（产品底层原则）

- C 端内容属于用户的个人数字资产；

- B 端仅在“本次婚礼采访及交付所必需范围内”获得查看与引用能力；

- 因此：**B 端不可对 C 端资产产生任何写入影响**，以确保资产独立性与合规边界清晰。
