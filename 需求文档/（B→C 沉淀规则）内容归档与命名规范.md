# （B→C 沉淀规则）内容归档与命名规范

# 1.1 目的


B 端采访完成后，系统将采访产物**自动沉淀到受访者的 C 端指定板块**，并以**固定 UI 名称**展示，保证：


- 用户可直达成果位置；

- 同一身份+同一采访内容类型，命名与归档位置一致；

- 可验收、可回归测试。




# 1.2 受访者身份（Role）范围（固定 8 种）


受访者身份仅允许以下 8 种（UI 与业务以此为准）：


1. 新郎

1. 新娘

1. 男方父亲

1. 男方母亲

1. 女方父亲

1. 女方母亲

1. 男方其他亲友

1. 女方其他亲友



说明：


- “其他长辈/朋友”等不单独作为身份入口出现，统一通过 **男方其他亲友 / 女方其他亲友** 进入采访通道。

- 具体是“长辈”还是“朋友”，由 **AI 在采访过程中追问确认**（例如：“Ta 是您的长辈还是朋友？”），并作为归档路由的判定条件之一。




# 1.3 C 端沉淀板块范围（仅 3 个）


C 端沉淀板块仅包含以下 3 个，不涉及任何高隐私板块：


- **家族根源**

- **生命延续**

- **社会关系**




# 1.4 采访内容类型（固定 4 类）


B 端采访内容类型固定为：


- 原生家庭

- 成长轨迹

- 爱情故事

- 未来承诺

# 1.6 B 端回流跳转规则（与 P02 配套）


- B 端采访结束后，默认**直达本次产物的归档板块页面**。

- 落地页需提供“本次成果可见”的强反馈（形式不限）：例如提示条“已生成 X 篇内容”，并置顶/高亮本次生成条目。

- 若本次产物分散在多个板块：回流落地到“主板块”（优先级：家族根源 > 生命延续 > 社会关系）并提示“已归档到 X 个板块”。




# 1.7 验收口径（可测试）


1. 选择身份=男方母亲，采访内容=未来承诺 → 必须沉淀到【生命延续】，UI 名称=【传家·锦囊】。

1. 选择身份=男方其他亲友，AI 判定=朋友，采访内容=成长轨迹 → 必须沉淀到【社会关系】，UI 名称=【并肩·征途】。

1. 新郎采访内容=爱情故事 → 必须沉淀到【家族根源】，UI 名称=【家史·元年】。

1. 同一身份+同一内容类型，无论从何入口回流查看，沉淀板块与 UI 名称必须一致，不允许出现两套命名。
