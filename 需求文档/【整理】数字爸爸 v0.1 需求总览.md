# 数字爸爸 v0.1 需求总览（整理版）

> 本文档基于需求文档目录整理，供开发与产品快速查阅。**v0.1 为 MVP 版本，仅做最小可验证闭环。**

---

## 一、项目定位与目标

### 1.1 版本定位

- **版本**：v0.1（MVP）
- **目标**：跑通最小业务闭环，验证「B 端主持人 + C 端新人」之间的素材采集、确认入库与生成交付链路
- **核心理念**：数字爸爸不是「聊天直接生成」，而是：
  - **采访/对话 → 分板块小结 → 用户确认 → 入库 → 受控生成**

### 1.2 目标闭环（验收口径）

1. 主持人能创建项目并拿到分享入口（二维码/链接）
2. 新郎、新娘能分别扫码进入，选择身份并开始采访
3. 采访严格按 4 个板块推进
4. 每个板块结束必须出现一次板块小结（共 4 次）
5. 小结默认未确认；用户确认后该板块变为「已确认素材包」
6. B 端项目详情能看到新郎/新娘的四板块素材包状态
7. B 端可一键生成：开场白 / 新郎誓言 / 新娘誓言
8. 生成内容只使用已确认素材包，**禁止直接用原始对话原文写事实**
9. 生成结果可编辑（至少可在页面内修改文本并保存为本项目成品版本）

### 1.3 开发原则

- 先做最小闭环，不追求一步到位
- 先实现，再优化
- 不要把附录提示词当成主业务流程
- 不要自行扩展未来版本需求
- 如需求不清，先提问，不要擅自假设

## 三、核心业务闭环

### 3.1 主流程（最小路径）

```
Step 1: B 端创建项目并分发入口
  → 主持人登录 B 端 → 新建婚礼项目 → 系统生成专属采访入口（二维码/链接）→ 发给新郎、新娘

Step 2: C 端新人扫码进入并选择身份
  → 新郎扫码 → 选择「新郎」→ 勾选授权 → 开始采访
  → 新娘扫码 → 选择「新娘」→ 勾选授权 → 开始采访

Step 3: C 端多轮采访按 4 个板块串行推进
  → 板块 1：原生家庭
  → 板块 2：成长轨迹
  → 板块 3：爱情故事
  → 板块 4：未来承诺

Step 4: 每个板块产出「独立小结」并确认（核心机制）
  → 4 个板块 = 4 次阶段小结
  → 小结默认「未确认」，用户确认后该板块素材才算「已确认素材包」
  → 生成内容只能使用已确认素材包

Step 5: B 端生成交付物（最小三件套）
  → 婚礼开场白：综合新郎 + 新娘的已确认素材包
  → 新郎誓言：只用新郎的已确认素材包
  → 新娘誓言：只用新娘的已确认素材包
  → 生成后必须支持编辑（人机协同）
```

### 3.2 数据归属与边界（硬规则）

| 规则 | 说明 |
|------|------|
| C 端是源数据 | 新郎/新娘确认后的四板块素材包，沉淀为其个人内容资产 |
| B 端只读引用 | B 端能查看并引用「已确认素材包」，**不得反向修改 C 端内容** |
| 素材更新 | 若 C 端更新导致新版本，B 端提示「有更新」，可选择采用新版本用于本次交付 |

## 四、采访结构：4 个板块

### 4.1 板块清单（写死）

1. **原生家庭**
2. **成长轨迹**
3. **爱情故事**
4. **未来承诺**

- 板块名称可换，但「4 板块串行 + 每板块小结确认」是硬规则
- 每个板块有独立的提问目标与提示词配置

### 4.2 板块小结机制

#### 触发规则

- 每个板块结束时，系统必须触发一次该板块的小结卡片/页面（共 4 次）
- 小结出现后，用户可编辑/补充/确认
- 用户确认后，才进入下一板块或进入生成

#### 小结内容结构

| 字段 | 说明 |
|------|------|
| 标题 | {板块名}小结 |
| 关键人物 | 标签，可选 |
| 核心要点 | 最多 8 条，含事实类（事件/经历/时间/关系）与表达类（态度/金句/情绪高光） |
| 编辑能力 | 可改/可删/可新增条目 |
| 确认按钮 | 确认本板块小结（确认后进入「已确认素材包」） |

#### 确认硬规则

- 小结生成后默认「未确认」
- 用户点击确认后，该板块条目变为「已确认素材」
- **生成时只允许引用已确认素材**
- 禁止绕过确认直接用原始对话原文生成事实内容

#### 条目不足处理

- 若某板块小结确认条目 < 3：提示用户「补充一个要点」或继续对话补充
- 本期可直接阻止进入生成

## 五、B 端页面与功能

### 5.1 页面清单与跳转

| 编号 | 页面 | 功能 | 出口 |
|------|------|------|------|
| B-P01 | 登录页 | 手机号 + 短信验证码登录 | 登录成功 → P02 |
| B-P02 | 项目管理（列表） | 查看项目卡片、新建、查看详情、分享采访 | 新建 → P02A；详情 → P02C；分享 → P02B |
| B-P02A | 新建项目 | 新郎姓名、新娘姓名、婚礼日期；创建成功扣配额 1 次 | 成功 → 回 P02 |
| B-P02B | 分享采访链接 | 二维码 + 入口链接（复制/下载/打开） | 返回 |
| B-P02C | 项目详情 | 素材库（新郎/新娘四板块）+ 生成区（开场白/新郎誓言/新娘誓言） | 分享 → P02B；返回 → P02 |

### 5.2 项目详情页结构

**素材库（只两人）**

- 新郎素材：4 个板块的状态/内容摘要
- 新娘素材：4 个板块的状态/内容摘要
- 展示：是否已完成 / 是否已确认 / 是否有更新

**生成区（只三件套）**

- 开场白（新郎 + 新娘已确认素材包）
- 新郎誓言（只新郎已确认素材包）
- 新娘誓言（只新娘已确认素材包）
- 支持：AI 生成 / 查看 / 编辑

### 5.3 登录规则

- 手机号：11 位，格式校验
- 验证码：6 位，获取后 60 秒倒计时
- 失败提示：验证码错误、过期、未开通账号、账号禁用、系统异常

## 六、C 端页面与功能

### 6.1 页面清单与跳转

| 编号 | 页面 | 功能 | 出口 |
|------|------|------|------|
| C-P05 | 扫码后采访页（选择身份） | 新郎/新娘二选一；授权勾选必须勾选才可开始 | 开始采访 → 采访对话页 |
| C-Interview | 采访对话页 | 4 板块串行多轮采访；语音优先 + 可切文字 | 板块结束 → 板块小结页 |
| C-Summary | 板块小结页/卡片 | 标题、核心要点、编辑、确认 | 确认 → 回采访页下一板块；四板块全确认 → 采访完成 |

### 6.2 身份选择页规则

- v0.1 只保留：**新郎 / 新娘**
- 父母/亲友入口：隐藏或置灰，不开放
- 授权勾选必须勾选才可开始

### 6.3 采访对话页规则

- 支持语音输入优先（强烈建议）+ 可切文字
- 串行推进四个板块
- 每板块结束必须弹出该板块小结并要求确认

## 九、统一后台（平台管理端）

### 9.1 角色与权限

| 角色 | 数据范围 | 典型功能 |
|------|----------|----------|
| 主持人 (host) | 仅自己的项目、采访对象、生成物 | 项目管理、采访对象、生成物、生成日志 |

- 同一套后台，按角色展示不同菜单与数据
- 主持人不可访问他人数据
- 平台管理员可审计全平台操作
