# 提示词与场景数据合理性分析

基于《提示词与场景说明文档》与当前数据库内容对比，结论与建议如下。

---

## 一、结论概览

| 维度           | 是否合理 | 说明 |
|----------------|----------|------|
| 表结构         | 部分合理 | `prompt_scene_item` 仍保留 `template_id`，与文档「改造后」不一致 |
| 提示词（prompt） | 部分合理 | 缺少 3 条 QUESTION 类提示词；交付物类 content_type 已为 GENERATE，符合文档 |
| 场景（prompt_scene） | 不合理 | 仅 5 个场景，文档要求 18 个，缺失 13 个 |
| 场景项（prompt_scene_item） | 部分合理 | 已有项均引用有效 prompt_code；因场景缺失导致大量场景项未配置 |

**总体**：当前数据很可能是「只执行了部分迁移/种子脚本」的结果（例如只跑了 V16 的补全场景，未跑全 V14 的完整场景），与文档第三章「现有场景列表」及 V14 脚本设计不一致，需要补全场景与提示词后再做联调与验收。

---

## 二、表结构对照

### 2.1 prompt 表

- 文档要求：`id, code, name, content_type, description, status, version_no, content, is_active, created_at, created_by, updated_at`，唯一约束 `(code, version_no)`。
- 当前库：字段齐全（含 `content_type` 枚举 SYSTEM_ROLE / QUESTION / FOLLOW_UP / SUMMARY / GENERATE / TEXT），有 `code` 索引。**合理。**

### 2.2 prompt_scene 表

- 文档未细列字段；当前有 `code, name, scope, board_code, role_type, description, status` 等。与文档中「场景编码、板块、角色」等描述一致。**合理。**

### 2.3 prompt_scene_item 表（与文档不一致）

- 文档（4.1）：**修改**为「列 `template_id` 改为 `prompt_code`（VARCHAR(64)）」，即场景项只通过 `prompt_code` 关联提示词。
- 当前库：**同时存在** `template_id`（bigint NOT NULL）和 `prompt_code`（varchar(64) NOT NULL）。当前所有 6 条记录的 `template_id=0`，实际绑定均用 `prompt_code`。
- **结论**：逻辑上已按 `prompt_code` 使用，但表结构未按文档完成改造，仍保留 `template_id`，存在冗余与歧义。建议后续迁移中**删除 `template_id` 列**，并确认唯一约束为 `(scene_id, prompt_code)`。

## 三、提示词（prompt）数据

### 3.1 文档与脚本预期

- 文档 1.1：提示词为最小可管理单位，同一 `code` 多版本用 `version_no` + `is_active=1` 标识当前生效。
- V14 种子：约 10 条提示词，包括开场白/新郎新娘誓言、原生家庭/成长/爱情故事的系统角色与**提问**、通用板块小结等。
- V16：在部分 code 上更新/插入更长正文，并新增 `FUTURE_PROMISE_SYSTEM` 等。

### 3.2 当前库情况（8 条）

| code                       | name               | content_type | 说明     |
|----------------------------|--------------------|-------------|----------|
| OPENING_SPEECH_MAIN        | 婚礼开场白-主文案   | GENERATE    | 符合文档 |
| GROOM_VOW_MAIN             | 新郎誓言-主文案    | GENERATE    | 符合文档 |
| BRIDE_VOW_MAIN             | 新娘誓言-主文案    | GENERATE    | 符合文档 |
| FAMILY_ORIGIN_SYSTEM       | 原生家庭-系统角色  | SYSTEM_ROLE | 符合文档 |
| GROWTH_SYSTEM              | 成长轨迹-系统角色  | SYSTEM_ROLE | 符合文档 |

### 3.3 缺失的提示词（与 V14 对比）

| code                 | 用途说明           |
|----------------------|--------------------|

若业务上采访/板块小结需要「系统角色 + 提问列表」两条一起用，则**必须补回这 3 条提示词**（或等价 code），否则对应场景不完整。

## 四、场景（prompt_scene）数据

### 4.1 文档第三章要求（18 个场景）

- **交付物 DELIVERABLE**（3）：`DELIVERABLE_OPENING_SPEECH`、`DELIVERABLE_GROOM_VOW`、`DELIVERABLE_BRIDE_VOW`
- **板块小结 BOARD_SUMMARY**（5）：`BOARD_SUMMARY_COMMON`、`BOARD_SUMMARY_FAMILY_ORIGIN`、`BOARD_SUMMARY_GROWTH`、`BOARD_SUMMARY_LOVE_STORY`、`BOARD_SUMMARY_FUTURE_PROMISE`
- **采访 BOARD_INTERVIEW**（10）：  
  `BOARD_INTERVIEW_FAMILY_ORIGIN_GROOM/BRIDE`、`BOARD_INTERVIEW_GROWTH_GROOM/BRIDE`、  
  `BOARD_INTERVIEW_LOVE_STORY_GROOM/BRIDE`、`BOARD_INTERVIEW_FUTURE_PROMISE_GROOM/BRIDE`、  
  `BOARD_INTERVIEW_COMMON_GROOM/BRIDE`

### 4.2 当前库仅有 5 个场景

| id | code                                | scope         | 说明           |
|----|-------------------------------------|---------------|----------------|
| 1  | BOARD_SUMMARY_FUTURE_PROMISE        | BOARD_SUMMARY | 文档中有       |
| 2  | BOARD_INTERVIEW_GROWTH_BRIDE        | BOARD_INTERVIEW | 文档中有     |
| 3  | BOARD_INTERVIEW_LOVE_STORY_BRIDE   | BOARD_INTERVIEW | 文档中有     |
| 4  | BOARD_INTERVIEW_FUTURE_PROMISE_GROOM| BOARD_INTERVIEW | 文档中有     |
| 5  | BOARD_INTERVIEW_FUTURE_PROMISE_BRIDE| BOARD_INTERVIEW | 文档中有     |

### 4.3 缺失场景汇总（13 个）

- **DELIVERABLE**：3 个全缺  
  `DELIVERABLE_OPENING_SPEECH`、`DELIVERABLE_GROOM_VOW`、`DELIVERABLE_BRIDE_VOW`
- **BOARD_SUMMARY**：缺 4 个  
  `BOARD_SUMMARY_COMMON`、`BOARD_SUMMARY_FAMILY_ORIGIN`、`BOARD_SUMMARY_GROWTH`、`BOARD_SUMMARY_LOVE_STORY`
- **BOARD_INTERVIEW**：缺 6 个  
  `BOARD_INTERVIEW_FAMILY_ORIGIN_GROOM`、`BOARD_INTERVIEW_FAMILY_ORIGIN_BRIDE`、

因此，**交付物生成、板块小结（除未来承诺外）、以及大部分采访场景**在按「场景编码」取提示词时都会失败或无法使用，与文档描述不一致。

## 五、场景项（prompt_scene_item）数据

### 5.1 当前 6 条场景项

| scene_code                         | prompt_code              | display_order | usage_mode |
|------------------------------------|--------------------------|---------------|------------|
| BOARD_SUMMARY_FUTURE_PROMISE       | FUTURE_PROMISE_SYSTEM    | 0             | PREPEND    |
| BOARD_SUMMARY_FUTURE_PROMISE       | BOARD_SUMMARY_COMMON_PROMPT | 1          | APPEND     |
| BOARD_INTERVIEW_GROWTH_BRIDE      | GROWTH_SYSTEM            | 0             | PREPEND    |
| BOARD_INTERVIEW_LOVE_STORY_BRIDE   | LOVE_STORY_SYSTEM        | 0             | PREPEND    |
| BOARD_INTERVIEW_FUTURE_PROMISE_GROOM | FUTURE_PROMISE_SYSTEM  | 0             | PREPEND    |
| BOARD_INTERVIEW_FUTURE_PROMISE_BRIDE | FUTURE_PROMISE_SYSTEM  | 0             | PREPEND    |

- 所有 `prompt_code` 均在 `prompt` 表中存在且当前有 `is_active=1` 的版本，**引用有效**。
- 顺序与 PREPEND/APPEND 用法与文档 1.2 描述一致。

### 5.2 与文档/V14 的差异

- 文档与 V14：交付物场景应为「单条 APPEND」（如 OPENING_SPEECH_MAIN / GROOM_VOW_MAIN / BRIDE_VOW_MAIN）；板块小结/采访多为「PREPEND 系统角色 + APPEND 提问 + APPEND 小结」等。当前库因**缺少上述 13 个场景**，导致这些场景项完全不存在。
- 现有 5 个采访/板块小结场景中，采访类只有「系统角色 PREPEND」，没有绑定 QUESTION 类提示词；若产品上需要「角色+提问」一起下发，需在补全场景后为对应场景增加对 `FAMILY_ORIGIN_QUESTIONS` / `GROWTH_QUESTIONS` / `LOVE_STORY_QUESTIONS` 的引用（并先补全这 3 条 prompt）。

## 六、与调用链的对应关系（文档 2.1）

| 业务           | 场景编码示例                     | 当前是否可解析 |
|----------------|----------------------------------|----------------|
| 交付物生成     | DELIVERABLE_OPENING_SPEECH 等   | 否（场景缺失） |
| 板块小结       | BOARD_SUMMARY_*                 | 仅 FUTURE_PROMISE 可解析，其余 4 个缺失 |
| 采访会话       | BOARD_INTERVIEW_*_GROOM/BRIDE   | 仅 4 个场景存在，其余 6 个缺失 |

因此，`DeliverableService`、`BoardSummaryService`、`BoardStoryService`、`InterviewSessionService` 中按 `sceneCode` 调用 `PromptSupplyService.getPromptsBySceneCode(sceneCode)` 时，多数 sceneCode 会查不到场景或场景项，**数据与文档设计不一致**。

## 七、建议行动

1. **补全场景**  
   按文档第三章与 V14（及 V16 中补全部分）执行或整理出完整 `INSERT`，确保 18 个场景全部存在（3 DELIVERABLE + 5 BOARD_SUMMARY + 10 BOARD_INTERVIEW）。

2. **补全提示词**  
   若保留「系统角色 + 提问」的用法，执行 V14 中关于 `FAMILY_ORIGIN_QUESTIONS`、`GROWTH_QUESTIONS`、`LOVE_STORY_QUESTIONS` 的插入（或等价内容）。

3. **补全场景项**  
   对上述 13 个缺失场景，按 V14/V16 的绑定关系为每个场景插入对应的 `prompt_scene_item`（`scene_id`, `prompt_code`, `display_order`, `usage_mode`），并保证引用的 `prompt_code` 在 `prompt` 表中存在且生效。

4. **表结构清理（可选但推荐）**  
   在确认应用与迁移脚本均只使用 `prompt_code` 后，执行一次迁移：从 `prompt_scene_item` 中删除 `template_id` 列，并确认唯一约束为 `(scene_id, prompt_code)`，与文档 4.1 一致。

5. **回归验证**  
   补全后对文档 2.1 中的调用链做一次回归：对每个列出的 sceneCode 调用 `GET /api/admin/prompts/scene/{sceneCode}` 与 `.../combined`，确认返回的提示词列表与合并内容符合预期。
