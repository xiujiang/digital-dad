# 提示词数据生成分析

本文档结合 **当前项目表结构**、**《提示词与场景说明文档》** 以及 **需求文档/提示词/** 下的 7 份需求，说明：要写哪些表、每张表存什么、需求与场景/提示词的对应关系，便于后续生成 SQL 或脚本。

---

## 一、涉及的表（3 张）

| 表名 | 说明 | 主要字段 |
|------|------|----------|
| **prompt** | 提示词主表。同一 `code` 多行表示多版本，`is_active=1` 的一行为当前生效。 | code, name, content_type, description, status, version_no, **content**, is_active, created_at, updated_at |
| **prompt_scene** | 场景主表。表示「在某种业务下用哪几条提示词、按什么顺序」。 | code, name, scope, board_code, role_type, description, status, created_at, updated_at |
| **prompt_scene_item** | 场景项。场景与提示词的绑定：某场景下用哪个 prompt_code、顺序、用法。 | scene_id, **prompt_code**, display_order, usage_mode, created_at |

供给时：按 **场景编码**（如 `DELIVERABLE_OPENING_SPEECH`、`BOARD_INTERVIEW_FAMILY_ORIGIN_GROOM`）查场景 → 取该场景下所有 scene_item 的 prompt_code → 在 prompt 表中取当前生效（is_active=1）的 content，按 display_order、usage_mode 拼接。

---

## 二、表字段与内容要点

### 2.1 prompt 表

| 字段 | 含义 | 本次生成要点 |
|------|------|----------------|
| code | 逻辑标识，全局唯一同一 code 多版本用 version_no 区分 | 如 OPENING_SPEECH_MAIN、FAMILY_ORIGIN_SYSTEM、BOARD_SUMMARY_DIALOG 等 |
| name | 展示用名称 | 中文简短名，如「婚礼开场白-主文案」「原生家庭-系统角色」 |
| content_type | 内容类型 | SYSTEM_ROLE / QUESTION / FOLLOW_UP / SUMMARY / GENERATE / TEXT，见下节 |
| description | 说明 | 可选，便于管理端区分 |
| status | 启用状态 | 一般 ENABLED |
| version_no | 版本号 | 首版填 1；(code, version_no) 唯一 |
| **content** | 提示词正文 | **需求文档中的完整长文案放这里** |
| is_active | 是否当前生效 | 每个 code 只应有一条 is_active=1 |
| created_at / updated_at | 时间 | NOW() 即可 |

**content_type 与需求文档对应：**

- **GENERATE**：直接生成成品的提示词 → 需求「主持人开场白」「新郎/新娘誓词」的整段文案。
- **SYSTEM_ROLE**：系统角色 + 心法 + 访谈流 + 异常处理 → 需求「原生家庭」「成长轨迹」「爱情故事」「未来承诺」的访谈官设定与结构化访谈流。
- **SUMMARY**：对对话做结构化提炼（含 JSON 输出规范）→ 需求「对话小结」。
- **QUESTION** / **FOLLOW_UP**：若拆成「单独提问列表」或「追问策略」可选用；当前需求文档中访谈问题多写在 SYSTEM_ROLE 内，可继续用 SYSTEM_ROLE 一条，或拆出 QUESTION 按需。

### 2.2 prompt_scene 表

| 字段 | 含义 | 取值说明 |
|------|------|----------|
| code | 场景编码，唯一 | 文档规定：DELIVERABLE_xxx / BOARD_SUMMARY_xxx / BOARD_INTERVIEW_xxx_GROOM|BRIDE |
| name | 场景名称 | 中文，如「婚礼开场白」「原生家庭·板块小结」「采访-未来承诺-新郎」 |
| scope | 适用范围 | DELIVERABLE / BOARD_SUMMARY / BOARD_INTERVIEW |
| board_code | 板块编码（仅 BOARD_* 场景用） | FAMILY_ORIGIN, GROWTH, LOVE_STORY, FUTURE_PROMISE；通用兜底为 NULL |
| role_type | 角色（仅 BOARD_INTERVIEW 用） | GROOM / BRIDE / COMMON |
| description | 说明 | 可选 |
| status | 启用状态 | ENABLED |

### 2.3 prompt_scene_item 表

| 字段 | 含义 | 说明 |
|------|------|------|
| scene_id | 所属场景 id | 由 prompt_scene 插入后查 code 得到 |
| prompt_code | 绑定的提示词 code | 对应 prompt.code，供给时按 code 取当前生效 content |
| display_order | 顺序 | 0, 1, 2… 决定拼接顺序 |
| usage_mode | 用法 | PREPEND（拼前）/ APPEND（拼后）/ STANDALONE |

## 三、需求文档与表数据的对应关系

### 3.1 需求文档 → 提示词（prompt 表）

| 需求文档 | 建议 prompt code | content_type | content 来源 |
|----------|------------------|--------------|-------------|
| **主持人开场白** | OPENING_SPEECH_MAIN | GENERATE | 需求全文：角色设定、输入数据源、词汇锚点、四乐章结构、输出规范 |
| **新郎/新娘誓词** | GROOM_VOW_MAIN / BRIDE_VOW_MAIN | GENERATE | 需求全文：角色设定、输入数据源、核心纪律、四段结构、输出格式 |
| **对话小结** | BOARD_SUMMARY_DIALOG（或沿用 BOARD_SUMMARY_COMMON_PROMPT 名但内容替换） | SUMMARY | 需求全文：角色设定、核心提炼纪律、输入/输出 JSON 结构及字段规则 |
| **原生家庭** | FAMILY_ORIGIN_SYSTEM | SYSTEM_ROLE | 需求全文：角色设定、访谈核心心法、三阶段访谈流、异常处理 |
| **成长轨迹** | GROWTH_SYSTEM | SYSTEM_ROLE | 需求全文：角色设定、心法、三阶段访谈流、异常处理、开发建议可放 description 或省略 |
| **爱情故事** | LOVE_STORY_SYSTEM | SYSTEM_ROLE | 需求全文：角色设定、心法、三阶段访谈流、异常处理、开发建议同上 |
| **未来承诺** | FUTURE_PROMISE_SYSTEM | SYSTEM_ROLE | 需求全文：角色设定、心法、三阶段访谈流、异常处理 |

当前 V14 里已有 FAMILY_ORIGIN_QUESTIONS、GROWTH_QUESTIONS 等：需求文档中「提问」多已写在 SYSTEM 的访谈流里，可二选一：  
- 要么**只用 SYSTEM 一条**（推荐），把开场话术、主问题、追问策略都放在同一 content；  
- 要么保留 QUESTIONS 条，content 里写「请根据当前板块生成 5～8 个开放式问题」等简短说明，与现有 V14 一致。  

若采用「只保留 SYSTEM 一条」，则场景项只绑 SYSTEM，不再绑 QUESTIONS。

### 3.3 场景项（prompt_scene_item）绑定思路

- **DELIVERABLE_xxx**：每个场景 1 条 item，prompt_code = OPENING_SPEECH_MAIN / GROOM_VOW_MAIN / BRIDE_VOW_MAIN，display_order=0，usage_mode=APPEND（或 STANDALONE）。
- **BOARD_SUMMARY_xxx**：  
  - 若小结用「一条通用 SUMMARY 提示词」：每个 BOARD_SUMMARY_xxx 场景绑 1 条，prompt_code = BOARD_SUMMARY_DIALOG（或 BOARD_SUMMARY_COMMON_PROMPT），APPEND。  
  - 若某板块要单独小结提示词，可再增加对应 code 的 item。
- **BOARD_INTERVIEW_xxx_GROOM/BRIDE**：每个场景 1 条 item，prompt_code = 对应板块的 SYSTEM（如 FAMILY_ORIGIN_SYSTEM、FUTURE_PROMISE_SYSTEM），PREPEND，display_order=0。若保留 QUESTIONS 条，可再绑一条 display_order=1，APPEND。

## 四、与当前项目的衔接点

1. **场景编码生成规则**（见《提示词与场景说明文档》2.1）：  
   - 交付物：`DELIVERABLE_` + ContentType  
   - 板块小结：`BOARD_SUMMARY_` + boardCode，无则 `BOARD_SUMMARY_COMMON`  
   - 采访：`BOARD_INTERVIEW_` + boardCode + `_` + 角色  

2. **供给链**：DeliverableService / BoardSummaryService / InterviewSessionService 最终都调用 `PromptSupplyService.getPromptsBySceneCode(sceneCode)`（或 getDeliverablePrompts / getSummaryPrompts / getInterviewPrompts），按 scene 的 item 的 prompt_code 从 prompt 表取 is_active=1 的 content。因此只要 **prompt 的 content 换成需求文档全文**，**场景与 scene_item 与文档一致**，即可生效。

3. **现有 V14**：  
   - 已有部分 prompt（code 如 OPENING_SPEECH_MAIN、FAMILY_ORIGIN_SYSTEM 等）和部分场景/场景项，但 prompt.content 为简短占位。  
   - 生成数据时建议：  
     - **更新**现有 prompt 的 `content` 为需求文档对应全文；  
     - **补全** FUTURE_PROMISE 相关场景与提示词；  
     - **补全** 成长轨迹/爱情故事 BRIDE 采访场景（若代码已按 GROOM/BRIDE 区分）；  
     - **对话小结** 使用需求文档中的 JSON 提炼提示词，更新或新增一条 SUMMARY 类型 prompt 并绑到 BOARD_SUMMARY_* 场景。

---

## 五、生成数据时建议顺序

1. **prompt**：按上表插入/更新，content 从 需求文档/提示词/ 中对应文件读取并转义后写入。  
2. **prompt_scene**：插入上节所列所有场景（含 FUTURE_PROMISE 与缺的 BRIDE）；若用 INSERT IGNORE 或 ON CONFLICT 可重复执行。  
3. **prompt_scene_item**：按场景 code 查 scene_id，再插入 (scene_id, prompt_code, display_order, usage_mode)。

这样即可做到：**表结构不变、供给逻辑不变**，仅用「完整提示词内容 + 完整场景与绑定」生成数据，与当前项目及《提示词与场景说明文档》一致。
