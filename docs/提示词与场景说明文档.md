# 提示词与场景说明文档

本文档整理「提示词」「提示词模板」「提示词场景」相关概念、改造内容及当前使用方式。

---

## 一、概念说明（改造后）

### 1.1 提示词（Prompt）

- **含义**：一条可配置的、带版本的提示词内容，是系统里**最小可管理单位**。
- **数据**：表 `prompt`。同一 **code** 多行表示多版本，其中 **is_active=1** 的一行为当前生效。
- **字段要点**：`code`（逻辑标识）、`name`、`content_type`、`description`、`status`、`version_no`、`content`（正文）、`is_active`。
- **与业务类型的关系**：表内没有「开场白」「新娘誓词」等业务枚举；这些是**交付物类型**（ContentType）和**场景编码**里的概念，提示词通过被场景引用而参与不同业务。

### 1.2 提示词场景（PromptScene）

- **含义**：一个**使用场景**，表示「在某种业务下用哪几条提示词、按什么顺序、如何拼接」。
- **数据**：表 `prompt_scene`（场景主表）+ `prompt_scene_item`（场景下的条目）。
- **场景项**：每条 `prompt_scene_item` 关联一个提示词 **code**（`prompt_code`）、`display_order`、`usage_mode`（PREPEND/APPEND/STANDALONE）。取内容时按 code 查 `prompt` 表中当前生效行。

### 1.3 改造前 vs 改造后

| 改造前 | 改造后 |
|--------|--------|
| **提示词模板**（PromptTemplate）：仅身份+元数据，无正文 | **提示词**（Prompt）：身份+元数据+正文+版本，一张表 |
| **提示词版本**（PromptVersion）：存正文、version_no、is_active | 合并进 `prompt`，同一 code 多行即多版本 |
| 场景项引用 **template_id**（模板主键） | 场景项引用 **prompt_code**（提示词编码） |
| 业务/接口按「场景」取提示词 | 不变，仍只按**场景编码**取 |

## 二、场景在系统中的使用位置

### 2.1 场景编码的生成规则

| 业务 | 场景编码规则 | 调用链 |
|------|----------------|--------|
| **交付物生成** | `DELIVERABLE_` + 交付物类型 | DeliverableService → getDeliverablePrompts(contentType) → sceneCode 如 `DELIVERABLE_OPENING_SPEECH` |
| **板块小结 / 故事** | `BOARD_SUMMARY_` + 板块 code，无则 `BOARD_SUMMARY_COMMON` | BoardSummaryService、BoardStoryService → getSummaryPrompts(boardCode) |
| **采访会话** | `BOARD_INTERVIEW_` + 板块 code + `_` + 角色 | InterviewSessionService → getInterviewPrompts(boardCode, role) → 如 `BOARD_INTERVIEW_FAMILY_ORIGIN_GROOM` |

所有「按场景取提示词」最终都调用 `PromptSupplyService.getPromptsBySceneCode(sceneCode)`。

### 2.2 管理端按场景预览

- `GET /api/admin/prompts/scene/{sceneCode}`：按场景编码返回该场景下的提示词列表。
- `GET /api/admin/prompts/scene/{sceneCode}/combined`：按场景编码返回合并后的完整提示词（预览发给模型的内容）。

### 2.3 场景的配置与管理

- **场景 CRUD**：`/api/admin/prompt-scenes`（列表、详情、创建、更新、删除）。
- **场景项**：在场景下 `addItem` / `updateItem` / `removeItem`，入参为 **promptCode**、displayOrder、usageMode。

## 四、改造内容汇总（模板与提示词合并）

### 4.1 数据库

| 变更 | 说明 |
|------|------|
| **新增表** `prompt` | 字段：id, code, name, content_type, description, status, version_no, content, is_active, created_at, created_by, updated_at；唯一约束 (code, version_no) |
| **修改** `prompt_scene_item` | 列 `template_id` 改为 `prompt_code`（VARCHAR(64)）；唯一约束改为 (scene_id, prompt_code) |
| **删除表** | `prompt_template`、`prompt_version`（若存在可手动执行 DROP；当前由 JPA ddl-auto 或人工维护） |

### 4.2 实体与 Repository

| 类型 | 变更 |
|------|------|
| **新增** | 实体 `Prompt`，Repository `PromptRepository`（按 code、is_active、code 列表等查询） |
| **修改** | 实体 `PromptSceneItem`：字段 `templateId` → `promptCode`；`PromptSceneItemRepository` 方法改为按 `promptCode`（如 existsBySceneIdAndPromptCode、existsByPromptCode） |
| **删除** | 实体 `PromptTemplate`、`PromptVersion`；Repository `PromptTemplateRepository`、`PromptVersionRepository` |

### 4.3 服务层

| 类型 | 变更 |
|------|------|
| **新增** | `PromptService`：提示词 CRUD（列表/详情/创建/更新/删除）+ 版本管理（按 code 列出版本、创建版本、激活版本、删除版本） |
| **修改** | `PromptSupplyService`：按 `prompt_code` 从 `prompt` 表取当前生效内容；`PromptSceneService`：addItem/updateItem 使用 `promptCode`，加载场景项时按 code 查 Prompt |
| **删除** | `PromptTemplateService`、`PromptVersionService` |

### 4.4 接口与 DTO

| 类型 | 变更 |
|------|------|
| **提示词管理** | `/api/admin/prompt-templates`：列表/详情/创建/更新/删除 改为使用 `PromptService`；创建时请求体需包含 **content**（首版正文）；响应为 `PromptResponse`（含 id, code, name, versionNo, content, isActive 等） |
| **版本管理** | 路径改为 `/api/admin/prompt-templates/{code}/versions`（按 **code** 而非 templateId）；列表/创建/激活/删除版本由 `PromptService` 提供 |
| **场景项** | 添加场景项请求体：**templateId** → **promptCode**（必填）；场景项响应：**templateId/templateCode/templateName** → **promptCode/promptName** |
| **供给 DTO** | `PromptContentDto`：**templateId/templateCode** → **promptId/promptCode** |
| **版本响应** | `PromptVersionResponse`：**templateId** → **code** |

## 五、管理员使用方式（改造后）

1. **按场景展示**：在管理端先列「提示词场景」，再进入某个场景查看/编辑该场景下的提示词配置。
2. **场景内的一条提示词**：由 **提示词 code**（对应某条 Prompt）+ **当前生效版本的正文**（content）唯一确定；管理端通过「提示词编码 + 正文」定位并编辑。
3. **绑定关系**：在场景详情中通过「添加条目」绑定 **promptCode**，并设置顺序（displayOrder）和用法（usageMode）；供给时按场景编码取该场景下所有条目的当前生效提示词内容并排序拼接。
