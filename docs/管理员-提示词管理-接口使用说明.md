# 管理员 - 提示词管理：接口使用说明

从业务角度说明：管理员进入平台「管理全部提示词」时，**先展示列表、再点击看详情** 应查哪些接口、展示哪些信息、如何调用。

---

## 一、第一屏：提示词列表

### 1.1 应查询的接口

| 接口 | 方法 | 说明 |
|------|------|------|
| 提示词列表 | `GET /api/admin/prompts` | 以「提示词」为管理单位，列表即提示词列表 |

**可选查询参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| contentType | string | 否 | 按内容类型筛选，如 TEXT |
| status | string | 否 | 按状态筛选：ENABLED / DISABLED |

**请求示例：**

```
GET /api/admin/prompts
GET /api/admin/prompts?status=ENABLED
```

**请求头：** `Authorization: Bearer {{adminToken}}`

---

### 1.2 接口返回与列表展示建议

**返回结构：** `data` 为数组，每项为「提示词」对象。

| 字段 | 类型 | 建议列表列展示 |
|------|------|----------------|
| id | number | 可隐藏，用于点击跳转时传参 |
| code | string | 建议展示，编码（唯一） |
| name | string | 建议展示，名称（主标题） |
| contentType | string | 建议展示，类型（如 TEXT） |
| description | string | 可选展示或仅详情用 |
| status | string | 建议展示，启用/停用 |
| activeVersionNo | number | 建议展示，「当前版本」或「生效版本号」 |
| createdAt | string | 可选展示，创建时间 |
| updatedAt | string | 可选展示，更新时间 |

**列表展示建议：**

- **必展示列：** 名称(name)、编码(code)、类型(contentType)、状态(status)、当前版本号(activeVersionNo)。
- **可选列：** 描述(description)、创建/更新时间。
- **行操作：** 点击某一行 → 进入该提示词的「详情/编辑」页（传 `id` 查详情，传 `code` 查版本列表）。

---

## 二、点击某一项：提示词详情

### 2.1 应调用的接口（按顺序）

| 顺序 | 接口 | 方法 | 用途 |
|------|------|------|------|
| 1 | 提示词详情 | `GET /api/admin/prompts/{id}` | 获取当前项的提示词元信息（名称、编码、类型、状态、当前生效版本号等） |
| 2 | 该提示词下的版本列表 | `GET /api/admin/prompts/{code}/versions` | 获取该提示词下所有版本（含每版的 content、是否生效），用于展示「版本列表」和「当前展示的提示词正文」 |

**请求示例（假设点击的提示词 id=5、code=WEDDING_INTRO）：**

```
GET /api/admin/prompts/5
GET /api/admin/prompts/WEDDING_INTRO/versions
```

**请求头：** `Authorization: Bearer {{adminToken}}`

---

### 2.2 提示词详情接口返回 → 详情页顶部/侧栏展示

| 字段 | 类型 | 建议展示位置 |
|------|------|--------------|
| id | number | 用于更新/删除等接口的 id |
| code | string | 详情页展示「编码」，并用于版本列表接口路径 `/api/admin/prompts/{code}/versions` |
| name | string | 详情页展示「名称」 |
| contentType | string | 详情页展示「类型」 |
| description | string | 详情页展示「描述」 |
| status | string | 详情页展示「状态」，并可做启用/停用操作 |
| activeVersionNo | number | 详情页展示「当前生效版本号」 |
| createdAt / updatedAt | string | 可选展示 |

---

### 2.3 版本列表接口返回 → 版本列表 + 提示词正文

**返回结构：** `data` 为数组，每项为「提示词版本」对象。

| 字段 | 类型 | 建议展示与用途 |
|------|------|----------------|
| id | number | 版本唯一 ID，用于「查看某版详情」或对比 |
| code | string | 所属提示词编码（响应中若返回） |
| versionNo | number | 版本号（1、2、3…），列表展示「版本号」 |
| content | string | **该版本的提示词正文**，用于在详情页展示「具体提示词内容」 |
| isActive | boolean | 是否当前生效，列表可标「当前生效」 |
| createdAt | string | 该版本创建时间 |
| createdBy | number | 创建人 ID，可选展示 |

**详情页展示建议：**

1. **上半部分 / 左侧：** 用「提示词详情」接口数据展示：名称、编码、类型、描述、状态、当前生效版本号。
2. **下半部分 / 右侧：**
   - **版本列表：** 用「版本列表」接口数据，展示版本号(versionNo)、是否生效(isActive)、创建时间(createdAt)；支持点击某一版。
   - **当前展示的提示词内容：** 默认展示 `isActive === true` 的那一版的 `content`；若用户点击其他版本，则展示该版本的 `content`（数据已包含在版本列表里，一般无需再调版本详情接口，除非你单独做了「版本详情」页再调 `GET .../versions/{versionId}`）。

## 三、整体调用流程小结

```
┌─────────────────────────────────────────────────────────────────┐
│  第一屏：提示词列表                                                │
│  调用：GET /api/admin/prompts [?contentType=&status=]             │
│  展示：表格/列表，列：名称、编码、类型、状态、当前版本号 等          │
│  交互：点击某一行 → 带 id、code 进入详情页（id 查详情，code 查版本） │
└─────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────┐
│  第二屏：提示词详情（点击某一项）                                   │
│  调用 1：GET /api/admin/prompts/{id}                             │
│          → 展示：提示词名称、编码、类型、描述、状态、当前生效版本号  │
│  调用 2：GET /api/admin/prompts/{code}/versions                  │
│          → 展示：版本列表（版本号、是否生效、创建时间）              │
│          → 展示：默认选中「当前生效版本」的 content 作为提示词正文   │
│          → 交互：切换版本时，展示对应版本的 content（无需再请求）   │
└─────────────────────────────────────────────────────────────────┘
```

## 四、可选增强（若产品需要）

- **列表筛选项：** 继续用 `GET /api/admin/prompts` 的 `contentType`、`status` 做筛选。
- **编辑/新建提示词：** 使用 `PUT /api/admin/prompts/{id}`、`POST /api/admin/prompts`（见 API 文档）。
- **编辑/新建版本（改提示词正文）：** 使用 `POST /api/admin/prompts/{code}/versions`、`PUT .../versions/{versionId}/activate` 等（见 API 文档）。
- **「该提示词被哪些场景引用」：** 若需在详情页展示「被用于场景 xxx」，目前需后端提供「按 promptCode 查场景」的接口，或前端从「场景列表 + 场景详情中的 items」自行反查。

按上述方式调用接口即可完成「列表 → 点击一项 → 展示该提示词信息 + 版本列表 + 具体提示词内容」的完整管理流程。
