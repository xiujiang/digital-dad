# 提示词模板与提示词合并改造方案

## 一、现状

### 1.1 表结构

| 表 | 含义 | 关键字段 |
|----|------|----------|
| `prompt_template` | 模板（身份+元数据） | id, code, name, content_type, description, status |
| `prompt_version` | 版本（正文+版本号） | id, template_id, version_no, content, is_active |
| `prompt_scene_item` | 场景-模板绑定 | scene_id, **template_id**, display_order, usage_mode |

- 场景项通过 `template_id` 引用模板；取内容时查该模板下 `is_active=1` 的 version。

### 1.2 涉及代码（按层）

- **实体**：`PromptTemplate`、`PromptVersion`、`PromptSceneItem`（含 templateId）
- **Repository**：`PromptTemplateRepository`、`PromptVersionRepository`、`PromptSceneItemRepository`（existsByTemplateId、existsBySceneIdAndTemplateId 等）
- **Service**：`PromptTemplateService`、`PromptVersionService`、`PromptSupplyService`、`PromptSceneService`
- **Controller**：`AdminPromptTemplateController`（/api/admin/prompt-templates）、`AdminPromptVersionController`（/api/admin/prompt-templates/{templateId}/versions）
- **DTO**：CreatePromptTemplateRequest、UpdatePromptTemplateRequest、PromptTemplateResponse、CreatePromptVersionRequest、PromptVersionResponse、AddSceneItemRequest（templateId）、PromptSceneItemResponse（templateId/templateCode/templateName）、PromptContentDto（templateId/templateCode）

---

## 二、目标设计

### 2.1 新表：`prompt`（一张表表示「提示词」= 身份 + 正文 + 版本）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| code | VARCHAR(64) | 逻辑标识，同一 code 多行 = 多版本 |
| name | VARCHAR(100) | 显示名 |
| content_type | VARCHAR(32) | SYSTEM_ROLE/QUESTION/… |
| description | VARCHAR(500) | 说明 |
| status | VARCHAR(20) | ENABLED/DISABLED |
| version_no | INT | 版本号，同 code 内递增 |
| content | TEXT | 提示词正文 |
| is_active | TINYINT(1) | 同 code 下仅一条为 1 |
| created_at | DATETIME | 创建时间 |
| created_by | BIGINT | 创建人 |
| updated_at | DATETIME | 更新时间 |

- 约束：`UNIQUE(code, version_no)`；业务约定同 code 下至多一条 `is_active=1`。
- 逻辑：**「一个提示词」= 一个 code**；**「当前生效的提示词」= 该 code 下 is_active=1 的那一行**。

### 2.2 场景项改为按 code 引用

| 表 | 变更 |
|----|------|
| `prompt_scene_item` | `template_id` → `prompt_code`（VARCHAR(64)），唯一约束改为 `UNIQUE(scene_id, prompt_code)` |

- 供给时：按 scene 取 items（含 prompt_code）→ 按 code 列表查 `prompt` 中 `code IN (…) AND is_active=1`，得到当前生效内容。

### 2.3 删除的表

- `prompt_template`
- `prompt_version`

## 三、修改清单（按执行顺序）

### 3.1 数据库迁移（Flyway）

1. **新建迁移脚本**（如 `V12__merge_prompt_template_and_version.sql`）：
   - 创建表 `prompt`（字段如上）。
   - 数据迁移：对每个 `prompt_template`，将其所有 `prompt_version` 插入 `prompt`（template 的 code/name/content_type/description/status + version 的 version_no/content/is_active/created_at/created_by）。
   - 在 `prompt_scene_item` 上：新增列 `prompt_code`（可空），`UPDATE prompt_scene_item i JOIN prompt_template t ON i.template_id = t.id SET i.prompt_code = t.code`。
   - 删除 `prompt_scene_item.template_id`，将 `prompt_code` 设为 NOT NULL，添加 `UNIQUE(scene_id, prompt_code)`。
   - 删除表 `prompt_version`、`prompt_template`。

## 四、接口兼容建议

- **路径**：若前端已用 `/api/admin/prompt-templates`，可保留路径，仅后端改为查 `prompt` 表。
- **列表**：返回「每个逻辑提示词一条」（当前生效），保留原有 list 的 contentType、status 筛选。
- **版本**：`GET/POST /api/admin/prompts/{code}/versions` 或 `GET/POST /api/admin/prompt-templates/{code}/versions`（用 code 替代原 templateId），返回结构可与原 PromptVersionResponse 兼容（去掉 templateId 即可）。
- **场景项**：addItem 的 body 从 `templateId` 改为 `promptCode`，属破坏性变更，需前端同步；场景详情里 items 的 templateId 改为 promptCode、templateName 改为 promptName。

## 五、实施顺序建议

1. 写 Flyway 迁移脚本并跑通（新建 prompt、迁数据、改 scene_item、删旧表）。
2. 新增 Prompt 实体与 PromptRepository。
3. 实现 PromptService（含列表/详情/创建/更新/删除/版本列表/创建版本/激活/删版本）。
4. 修改 PromptSupplyService、PromptSceneService 与 PromptSceneItemRepository、PromptSceneItem 及 DTO。
5. 修改两个 Admin Controller 与 DTO（Request/Response）。
6. 删除 PromptTemplate、PromptVersion 实体及 Template/Version 的 Repository/Service，并删除不再使用的 DTO。
7. 全量回归：场景按 code 取提示词、交付物/小结/访谈生成、管理端 CRUD 与版本管理。

---

## 六、风险与注意点

- **数据迁移**：确保每个 template 至少有一个 version，否则迁到 prompt 时无 content；若有 template 无 version，可插一条 content 为空或占位符的 version_no=1。
- **唯一约束**：同 code 下仅一条 is_active=1，需在应用层创建/激活版本时保证（或加 DB 约束/触发器，取决于实现）。
- **外键**：原 scene_item 有 FK 到 template，迁移后无 FK（引用 code），需保证管理端只能选择已存在的 prompt code。
