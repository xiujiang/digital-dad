# 语音转写配额设计方案（确认版）

## 一、业务规则

| 项目 | 约定 |
|------|------|
| 配额维度 | 按用户（user_id） |
| 周期 | 永久（不重置，用完即止） |
| 扣减依据 | 本次录音总时长（秒） |
| 单位 | 秒（存储、计算、记录统一用秒） |
| 默认额度 | 可配置，单位秒，存于 sys_config |
| 与会员关系 | 暂无，独立于会员套餐 |
| 控制方 | 后端 |
| HOST 用户 | **不做扣减**（主持人无限制） |
| **转写失败** | **未成功调用火山引擎则不扣减**（方案 B） |

---

## 二、数据设计

### 2.1 系统配置（sys_config）

| config_key | config_value | 说明 |
|------------|--------------|------|
| `speech.transcription` | `{"default_seconds": 3600}` | 新用户默认额度（秒），与 member.packages 同风格 |

**示例**（与现有 JSON 配置风格一致）：
```sql
INSERT INTO sys_config (config_key, config_value, description)
VALUES (
    'speech.transcription',
    JSON_OBJECT('default_seconds', 3600),
    '语音转写默认配额（秒），首次使用时懒加载初始化'
);
```

---

### 2.2 用户配额表（user_quota）——复用

沿用已有 `user_quota` 表，新增配额类型：

| 字段 | 说明 |
|------|------|
| user_id | 用户 ID |
| quota_type | 新增：`SPEECH_TRANSCRIPTION` |
| remaining | 剩余额度，单位：**秒**（INT） |
| total_used | 累计已使用，单位：**秒**（INT） |

**初始化**：C 端用户首次使用语音转写时 **懒加载**——查询时若无记录，则按 sys_config 的 `default_seconds` 插入一条 `user_quota`。后续若有注册流程，可改为注册时写入。

---

### 2.3 语音转写使用记录表（新建）

```sql
speech_transcription_usage
├── id                  BIGINT PK
├── user_id             BIGINT   -- 用户ID
├── duration_seconds    INT      -- 本次实际时长（秒）
├── deducted_seconds    INT      -- 本次实际扣减额（秒）
├── remaining_after     INT      -- 扣减后剩余额度（秒）
├── connect_id          VARCHAR  -- 可选，WebSocket connectId，用于追溯
├── created_at          DATETIME
└── 索引：idx_user_id, idx_created_at, idx_user_created
```

## 三、HOST 豁免逻辑

| 用户类型 | 是否扣减 | 说明 |
|----------|----------|------|
| WECHAT_USER | 是 | C 端参与者，扣减 |
| HOST | **否** | 主持人，不扣减、不校验 |
| SUPER_ADMIN | 否 | 超管，不扣减（可复用 HOST 逻辑） |

**实现**：在预检查与扣减前，若 `user_type = HOST` 或 `SUPER_ADMIN`，直接放行，不做任何配额读写。

## 四、流程设计

### 4.1 整体流程

```
用户发起语音转写
       │
       ▼
┌──────────────────────┐
│ 0. 是否为 HOST？      │
│    是 → 直接放行     │
└──────────────────────┘
       │ 否（WECHAT_USER）
       ▼
┌──────────────────────┐
│ 1. 额度预检查         │  ← WebSocket 握手前
│  - 查 user_quota     │
│  - remaining > 0 ?   │
└──────────────────────┘
       ├─ 否 → 拒绝连接，返回配额不足
       ▼ 是
┌──────────────────────┐
│ 2. 建立 WebSocket    │
│    连接火山引擎       │
└──────────────────────┘
       │ 火山连接失败 → 不扣减
       ▼ 成功
┌──────────────────────┐
│ 3. 收 PCM、转发火山   │
│    累加已转发 bytes   │
└──────────────────────┘
       │
       ▼ 收到 "end" 或 连接断开（含异常断开）
┌──────────────────────┐
│ 4. 扣减额度（仅 WECHAT_USER） │
│  - 是否曾成功转发 PCM 至火山？ │
│  - 否 → 不扣减       │
│  - 是 → 按已转发字节 │
│    duration_s=bytes/32000 │
│    remaining -= s    │
│  - 写入使用记录       │
└──────────────────────┘
```

---

### 4.2 额度预检查（WebSocket 建连前）

**逻辑**：
1. 若为 HOST / SUPER_ADMIN → 直接放行
2. 从 JWT 解析 `user_id`、`user_type`
3. 查询 `user_quota`，`quota_type = 'SPEECH_TRANSCRIPTION'`
4. 若不存在 → **懒加载**：按 sys_config 默认值初始化后，再查一次
5. 若 `remaining <= 0` → 拒绝 WebSocket 握手，返回 403

---

### 4.3 扣减流程（录音结束时）

**触发**：收到 `"end"` / `"stop"`，或 **WebSocket 异常断开**。

**扣减前置条件（方案 B）**：**仅当成功向火山引擎转发过 PCM 时才扣减**。若火山连接失败、或从未成功转发任何 PCM，则不扣减。

**逻辑**：
1. 若为 HOST / SUPER_ADMIN → 不扣减，直接返回
2. **判断本次会话是否曾成功向火山转发过 PCM** → 若否，不扣减，直接返回
3. 统计本次会话**已成功转发至火山**的 PCM 总字节数
4. `duration_seconds = bytes / 32000`（16k×16bit×1ch）
5. 若 `duration_seconds == 0` → 不扣减
6. 事务内 `SELECT user_quota FOR UPDATE`
7. 若 `remaining < duration_seconds` → 只扣 `remaining`，`remaining` 置 0
8. 更新 `user_quota.remaining`、`total_used`
9. 插入 `speech_transcription_usage`
10. 提交事务

**实现要点**：在 WebSocket 会话中维护「已成功转发至火山的字节数」；仅在成功调用 `conn.sendAudio()` 后累加，连接火山失败或转发异常时不累加。

---

### 4.4 方案 B：成功调用的判定

| 情形 | 是否扣减 | 说明 |
|------|----------|------|
| 火山 WebSocket 连接失败 | 否 | 从未建立与火山的连接 |
| 火山连接成功，但 full request 发送失败 | 否 | 未完成初始化，未接收/转发 PCM |
| 火山连接成功，但 C 端未发送任何 PCM 即断开 | 否 | 无数据转发 |
| 成功向火山转发过至少 1 字节 PCM | 是 | 按实际转发的字节数扣减 |

**判定方式**：会话级变量 `bytesForwardedToVolcano`，仅在实际调用火山 `sendAudio` 且无异常时累加。

---

### 4.5 配额初始化（懒加载）

**时机**：C 端用户（WECHAT_USER）**首次**使用语音转写时（WebSocket 预检查或 GET /speech-quota）。

**逻辑**：
1. 查询 `user_quota`，`quota_type = SPEECH_TRANSCRIPTION`
2. 若不存在 → 从 sys_config 读取 `default_seconds`，插入 `user_quota`，再查
3. 若存在 → 直接使用

**后续扩展**：若有明确的 C 端注册流程，可改为注册时写入。

## 五、接口设计

### 5.1 查询剩余额度（C 端）

**GET** `/api/c/speech-quota`

**响应**：
```json
{
  "code": 200,
  "data": {
    "remainingSeconds": 2700,
    "totalUsedSeconds": 900
  }
}
```

**说明**：HOST 调用可返回足够大的值或固定值，表示无需展示配额。

---

### 5.2 为个人增加配额（管理端）

**PUT** `/api/admin/users/{userId}/speech-quota`

或

**POST** `/api/admin/speech-quota/add`

**请求体**：
```json
{
  "addSeconds": 3600
}
```

**说明**：在 `user_quota.remaining` 上 **累加** `addSeconds`，不覆盖原值。

**权限**：仅超管（SUPER_ADMIN）。

---

### 5.3 WebSocket 行为

- 握手前校验额度（HOST 豁免）
- `remaining <= 0` 时拒绝，返回 403，如：`{"code": 403, "message": "语音转写额度已用完", "reason": "SPEECH_QUOTA_EXHAUSTED"}`

## 六、边界与异常

| 场景 | 处理方式 |
|------|----------|
| HOST / SUPER_ADMIN | 预检查与扣减均跳过 |
| 新用户、无配额记录 | 懒加载：首次使用时按默认值初始化 |
| remaining = 0 | 拒绝建连 |
| 本次 0 字节 | 不扣减 |
| 剩余 30 秒，录了 60 秒 | 只扣 30 秒，remaining 置 0 |
| 连接异常断开 | 按**已成功转发至火山**的 PCM 换算并扣减 |
| **火山引擎连接失败** | **不扣减**（未成功调用） |
| **未成功转发任何 PCM** | **不扣减**（如火山建连后即断、未收到 C 端数据等） |
| 配置缺失 | 兜底默认 3600 秒，打日志 |

## 九、实施顺序建议

1. 新建 `speech_transcription_usage` 表
2. 在 sys_config 插入 `speech.transcription` 配置
3. 在 `QuotaType` 中新增 `SPEECH_TRANSCRIPTION`
4. 实现配额服务：懒加载初始化、查询、扣减（含 HOST 豁免）
5. 实现 WebSocket 握手的额度预检查
6. 在 WebSocket 结束/断开时，按**已成功转发至火山**的字节扣减（方案 B）
7. 实现 `GET /api/c/speech-quota`
8. 实现 `POST /api/admin/speech-quota/add`（或等价接口）

## 十、完整对话流程下的需求确认

基于「进入项目 → 绑定身份 → 采访会话 → 语音转写 → 消息 → 提交 AI → 小结 → 确认 → 草稿」的完整流程，对配额与对话相关的需求点进行了核对，**当前无未覆盖的模糊点**。以下为已确认或已约定的事项：

| # | 需求点 | 结论 |
|---|--------|------|
| 1 | 纯文字消息（键盘输入） | 不经过语音，不扣配额 |
| 2 | 一轮对话多段录音 | 每段 = 一次 WebSocket，各扣一次，按实际 PCM 时长 |
| 3 | 连接后 0 字节即断开 | 不扣减 |
| 4 | 配额按用户不按会话 | 多项目、多会话共享同一用户配额 |
| 5 | audioUrl 上传录音 | 仅存储，无录音文件识别，不扣配额 |
| 6 | 配额耗尽时的体验 | 预检查拒绝建连；建议 C 端在进入页或录音前调 GET /speech-quota，remaining=0 时禁用录音并提示 |
| 7 | 火山引擎转写失败 | **方案 B**：未成功调用（连接失败、未转发任何 PCM）则不扣减；仅对已成功转发至火山的 PCM 扣减 |
| 8 | 多设备同时录音 | 共享同一用户配额，扣减用 FOR UPDATE 保证一致 |
