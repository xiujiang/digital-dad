# 微信分享流程与后端方案

## 一、微信分享在做什么

- 主持人（B 端）要**把采访入口分享给参与者**（发到微信群、好友、或生成二维码）。
- 参与者**在微信里打开**该链接/二维码后，应直接进入**小程序指定页**，并带上**分享参数**（即项目的 `share_token`），从而能调用 `GET /api/c/entry/{token}` 拿到项目信息并走完整 C 端链路。

你看到的 `#小程序://工行服务/LGqCamGnyeL3s4g` 这类文案，是**微信把「小程序 URL Scheme」渲染成的展示口令**，不是业务侧手写的。业务侧只需要生成并下发 **URL Scheme**（形如 `weixin://dl/business/?t=xxxx`），微信会负责展示和跳转。

---

## 二、两种形态与后端差异

| 形态 | 分享出去的内容 | 后端当前/需要做的 |
|------|----------------|-------------------|
| **H5 入口** | 普通 URL：`https://xxx.com/c/entry/{shareToken}` | ✅ 已有：`share_token`、`entryUrl`、第三方二维码 URL |
| **小程序入口** | 小程序 Scheme：`weixin://dl/business/?t=xxx`（在微信里显示为 `#小程序://...`） | ❌ 需新增：调微信「生成 URL Scheme」接口，返回 `openlink` 给前端 |

若 C 端以**小程序**为主，分享到微信时应优先用 **URL Scheme**，体验更好（直接打开小程序、带参数）。后端需要增加「为指定项目生成 Scheme」的能力。

---

## 三、微信 URL Scheme 生成流程（后端要做的）

### 3.1 总体流程

1. **拿 access_token**（与现有微信登录共用 appid/appsecret）
   ```http
   GET https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=APPID&secret=APPSECRET
   ```
   返回示例：`{ "access_token": "xxx", "expires_in": 7200 }`

2. **调「生成 URL Scheme」接口**
   ```http
   POST https://api.weixin.qq.com/wxa/generatescheme?access_token=ACCESS_TOKEN
   Content-Type: application/json
   ```
   请求体示例：
   ```json
   {
     "jump_wxa": {
       "path": "pages/entry/index",
       "query": "token=项目对应的share_token"
     },
     "expire_type": 0,
     "expire_time": 1760000000,
     "env_version": "release"
   }
   ```
   - **path**：小程序里「扫码/链接进入」的落地页（如 `pages/entry/index`），由前端路由约定。
   - **query**：建议至少带 `token=<share_token>`，与现有 `GET /api/c/entry/{token}` 一致。
   - **expire_type**：0=按时间戳过期，1=按天数过期。
   - **expire_time**：Unix 时间戳（expire_type=0 时必填）。
   - **env_version**：`release`（正式）/ `trial`（体验）/ `develop`（开发）。

3. **成功返回**
   - 响应里会有 **openlink** 字段，即生成的 Scheme：`weixin://dl/business/?t=xxxx`。
   - 前端/ B 端可把该链接用于：复制到微信、生成二维码（用 openlink 当 content）、短信/邮件等。用户在微信内打开后，会显示为 `#小程序://...` 并拉起小程序并带上 query。

### 3.2 与现有配置的衔接

- 项目里已有 **微信小程序配置**：`app.wechat.miniprogram.app-id`、`app-secret`（如 `WeChatMiniprogramProperties`），可直接用于上述 `GET /cgi-bin/token`。
- 现有 **分享** 已具备：`share_token`、`entryUrl`、`qrCodeUrl`（H5）。新增的是：在「分享到微信且 C 端是小程序」时，多返回一个 **wechatScheme**（或类似字段），值为 `openlink`。

## 四、后端需要实现的能力汇总

| 序号 | 能力 | 说明 |
|------|------|------|
| 1 | 获取并缓存 access_token | 用现有 appid/appsecret 调 `GET /cgi-bin/token`，建议缓存至过期前若干分钟再刷新，避免频繁请求 |
| 2 | 调用 generateScheme | 用 access_token 调 `POST /wxa/generatescheme`，传入 path、query（含 share_token）、过期策略、env_version |
| 3 | 对外接口：按项目生成 Scheme | 输入：项目 ID（或 share_token）；校验：当前用户有权分享该项目；输出：`openlink`（及可选：用 openlink 生成的二维码 URL） |
| 4 | 与现有分享接口整合 | 在 `GET /api/b/projects/{id}/share`（或等价）的响应中，增加字段如 `wechatScheme`（小程序 Scheme）、`wechatSchemeQrCodeUrl`（可选），便于 B 端/小程序端「分享到微信」时使用 |

**path / query 约定（与前端对齐）**

- **path**：由前端小程序约定，例如 `pages/entry/index` 或 `pages/c/entry/index`，确保该页已发布。
- **query**：建议 `token=<share_token>`，与现有 C 端入口 `GET /api/c/entry/{token}` 一致，小程序落地页从 query 取 token 再调该接口。

## 五、接口设计建议

### 方案 A：在现有分享接口中扩展（推荐）

- **接口**：现有 `GET /api/b/projects/{id}/share`（或项目内等价分享接口）。
- **扩展响应**：在现有 `entryUrl`、`qrCodeUrl`、`shareToken` 基础上增加：
  - `wechatScheme`：字符串，即微信返回的 `openlink`（`weixin://dl/business/?t=xxx`），仅当配置了小程序且生成成功时返回。
  - `wechatSchemeQrCodeUrl`（可选）：用 `wechatScheme` 生成的二维码图片 URL，便于「下载二维码发微信」。

这样 B 端/小程序端一次请求即可拿到 H5 链接 + 小程序 Scheme，按形态选用。

### 方案 B：单独接口

- **接口**：如 `POST /api/b/projects/{id}/wechat-scheme` 或 `GET /api/b/projects/{id}/wechat-scheme`。
- **请求**：可带可选参数如 `expire_type`、`expire_time` 或 `expire_interval`、`env_version`（默认 release）。
- **响应**：`{ "openlink": "weixin://dl/business/?t=xxx" }` 及可选的二维码 URL。

适合「仅在小程序分享场景才调」、或希望与 H5 分享接口解耦时使用。

## 六、注意事项

1. **access_token**：全局唯一、有效期约 7200 秒，需**缓存**并在临近过期时刷新，避免超过微信调用频率限制。
2. **Scheme 配额与限频**：生成 Scheme 有每日配额与频率限制，见微信官方文档；若分享量大会考虑「按项目或按 token 复用已生成 Scheme」的策略（需结合过期时间）。
3. **path 必须已发布**：`jump_wxa.path` 必须是正式版/体验版中存在的页面，否则会报错（如 40165）。
4. **query 字符限制**：仅支持数字、大小写英文及部分特殊字符，且长度上限 1024；`share_token` 若为 UUID/短串一般无问题。
5. **安全**：生成 Scheme 的接口需校验「当前用户有权分享该项目」（与现有分享接口权限一致）。

## 七、前端调用流程（如何调用与使用）

### 7.1 谁在什么时机调用

- **B 端（主持人后台）**：在「分享采访」页加载时，或用户点击「获取分享链接/二维码」时，需要拿到当前项目的分享链接、二维码、以及（若为小程序形态）微信 Scheme。
- **小程序端**：若分享能力也在小程序内提供（例如主持人在小程序里进入某项目后点击「分享」），同样需要拿到 Scheme 用于转发到聊天或生成二维码。

以上场景都只需调用**同一个接口**，一次拿到 H5 与小程序两种形态所需数据。

### 7.2 调用哪个接口

**请求：**

```http
GET /api/projects/{projectId}/share
Authorization: Bearer <主持人或超管的 JWT>
```

- **路径参数**：`projectId` 为当前要分享的项目 ID。
- **认证**：必须带登录态（主持人只能查本人项目，超管可查任意项目）。

**响应（Result 包装下的 data）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| projectId | number | 项目 ID |
| shareToken | string | 分享令牌，C 端入口会用到 |
| entryUrl | string | H5 入口 URL（如 `https://xxx.com/c/entry/{shareToken}`） |
| qrCodeUrl | string | 基于 entryUrl 的二维码图片 URL，可直接用于展示或下载 |
| wechatScheme | string \| null | 微信小程序 URL Scheme（`weixin://dl/business/?t=xxx`）；未配置小程序或生成失败时为 null |
| wechatSchemeQrCodeUrl | string \| null | 基于 wechatScheme 的二维码图片 URL；无 scheme 时为 null |

前端无需区分「H5 项目」还是「小程序项目」：接口始终返回上述字段，根据 `wechatScheme` 是否为 null 决定是否展示「小程序分享」相关 UI。

### 7.3 前端如何使用返回数据

**1）H5 分享（链接 + 二维码）**

- **复制链接**：把 `data.entryUrl` 写入剪贴板，提示「已复制」。
- **展示/下载二维码**：用 `data.qrCodeUrl` 作为图片 `src` 展示，或提供「下载二维码」按钮（新开窗口打开该 URL 或转成 blob 下载）。

**2）小程序分享（发到微信内打开小程序）**

- 若 `data.wechatScheme == null`：不展示「小程序分享」或「复制小程序链接」等入口，仅保留 H5 链接/二维码即可。
- 若 `data.wechatScheme` 有值：
  - **复制 Scheme**：把 `data.wechatScheme` 写入剪贴板，用户粘贴到微信聊天发送；对方在微信内点击会以 `#小程序://...` 形式展示并打开小程序，并带上 `token=shareToken`。
  - **小程序二维码**：用 `data.wechatSchemeQrCodeUrl` 作为图片展示或下载，用户保存图片后发到微信，他人长按识别即可打开小程序并带 token。

**3）页面上的推荐展示方式**

- 同一分享页可同时提供：
  - 「采访入口链接」：只读框 + 复制按钮，内容为 `entryUrl`；
  - 「入口二维码」：图片 `qrCodeUrl`，用于扫码进 H5；
  - （当 `wechatScheme` 存在时）「小程序分享链接」：只读框 + 复制，内容为 `wechatScheme`；
  - （当 `wechatScheme` 存在时）「小程序二维码」：图片 `wechatSchemeQrCodeUrl`，用于发微信、长按识别打开小程序。

前端只需在进入分享页时**调用一次** `GET /api/projects/{id}/share`，然后根据返回的 `wechatScheme` 是否有值，决定是否渲染小程序相关的复制按钮和二维码区域。

### 7.4 小程序端作为「被打开方」时的处理

用户通过 Scheme 或小程序二维码打开小程序时，会进入约定落地页（当前后端约定为 **`pages/entry/index`**），且路径上会带 query：`token=<shareToken>`。

- 小程序在该页的 **onLoad**（或等价生命周期）里从 **options** 中取出 **token**（即 `shareToken`）。
- 拿到 token 后，调用 **`GET /api/c/entry/{token}`**（免登录）获取项目信息、可选角色等。
- 后续流程与 [C 端用户完整链路](C端用户完整链路（扫码到结束）.md) 一致：微信登录、选身份、进入采访等。

即：**前端只需在落地页从 query 取 token，并调 C 端入口接口，无需再调「分享」接口**；分享接口是给「发起分享的人」（主持人/B 端或小程序内分享入口）用的。

### 7.5 流程小结（前端视角）

1. **分享发起方**（B 端或小程序内分享页）：调用 `GET /api/projects/{id}/share`，用返回的 `entryUrl`、`qrCodeUrl` 做 H5 链接与二维码；若有 `wechatScheme`，用其做「复制小程序链接」和 `wechatSchemeQrCodeUrl` 做小程序二维码。
2. **参与方**（扫码/点链接进入）：若进的是小程序，在 `pages/entry/index` 从 query 取 `token`，调 `GET /api/c/entry/{token}`，再按 C 端链路完成登录、选身份、采访。

---

## 八、小结

- **微信分享**：把「采访入口」以链接或二维码形式发到微信；若 C 端是小程序，应使用**微信 URL Scheme**（生成后显示为 `#小程序://...`）。
- **后端**：已实现 access_token 缓存、generateScheme 调用，并在 `GET /api/projects/{id}/share` 中返回 `wechatScheme`、`wechatSchemeQrCodeUrl`。
- **前端**：分享页调用一次 `GET /api/projects/{id}/share`，用 `entryUrl`/`qrCodeUrl` 做 H5，用 `wechatScheme`/`wechatSchemeQrCodeUrl` 做小程序分享；小程序落地页 `pages/entry/index` 从 query 取 `token` 后调 `GET /api/c/entry/{token}` 走 C 端链路。
