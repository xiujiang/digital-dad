# 提示词板块 - 前端接口调用说明

面向前端：打开提示词板块后先展示**场景列表**，点击某场景再展示该场景下**当前生效的提示词列表**及状态等信息时的接口调用方式。

---

## 一、鉴权

所有接口均为**超管**能力，请求头需携带：

```
Authorization: Bearer {{adminToken}}
```

---

## 二、打开提示词板块 → 展示场景列表

**接口：** `GET /api/admin/prompt-scenes`

**作用：** 获取场景列表，用于列表页展示（场景编码、名称、作用域、状态等）。

**请求：**

- 路径：`GET /api/admin/prompt-scenes`
- Query 参数（均可选）：

| 参数        | 类型   | 说明 |
|-------------|--------|------|
| scope       | string | 作用域筛选，如 `DELIVERABLE`、`BOARD_SUMMARY`、`BOARD_INTERVIEW` |
| boardCode   | string | 板块编码 |
| roleType    | string | 角色类型，如 `GROOM`、`BRIDE`、`COMMON` |
| status      | string | 场景状态：`ENABLED`、`DISABLED`。**不传时后端默认只返回 ENABLED** |

**示例：**

- 查全部启用场景：`GET /api/admin/prompt-scenes`
- 只查交付物类：`GET /api/admin/prompt-scenes?scope=DELIVERABLE`
- 只查采访类：`GET /api/admin/prompt-scenes?scope=BOARD_INTERVIEW`

**响应 `data`：** 场景对象数组，**不包含**该场景下的提示词条目（items）。每项结构：

| 字段        | 类型   | 说明 |
|-------------|--------|------|
| id          | number | 场景 ID |
| code        | string | 场景编码（点击后按场景查提示词时要用） |
| name        | string | 场景名称 |
| scope       | string | 作用域 |
| boardCode   | string | 板块编码，可为 null |
| roleType    | string | 角色类型，可为 null |
| description | string | 描述 |
| status      | string | ENABLED / DISABLED |
| createdAt   | string | 创建时间，ISO 8601 |
| updatedAt   | string | 更新时间，ISO 8601 |

---

## 三、点击某场景 → 展示该场景下的提示词列表（当前生效 + 状态等信息）

有两种用法，可按需选一种或组合使用。

### 方式 A：按场景编码取「当前生效的提示词内容列表」（含正文、顺序、用法）

**接口：** `GET /api/admin/prompts/scene/{sceneCode}`

**作用：** 按场景编码获取该场景下**当前生效**的提示词列表（每条取的是当前激活版本的 content），适合「当前生效的提示词列表 + 正文预览」。

**请求：**

- 路径：`GET /api/admin/prompts/scene/{sceneCode}`
- 路径参数：`sceneCode` = 场景的 **code**（从步骤二列表项里的 `code` 取得，如 `DELIVERABLE_OPENING_SPEECH`、`BOARD_INTERVIEW_FAMILY_ORIGIN_GROOM`）

**响应 `data`：** 提示词内容对象数组，按 `displayOrder` 排序。每项结构：

| 字段         | 类型   | 说明 |
|--------------|--------|------|
| promptId     | number | 提示词主键（当前生效版本所在行 id） |
| promptCode   | string | 提示词编码 |
| versionNo    | number | 当前生效的版本号 |
| content      | string | 该条提示词正文 |
| displayOrder | number | 在场景中的展示/拼接顺序 |
| usageMode    | string | 使用方式：PREPEND / APPEND / STANDALONE |

**说明：** 此接口返回的是「供给层」用的数据，**不包含**提示词名称（name）、提示词状态（ENABLED/DISABLED）。若前端需要名称和状态，可配合方式 B 或由后端扩展本接口。

---

### 方式 B：按场景 ID 取场景详情（含绑定条目：提示词编码、名称、顺序、用法）

**接口：** `GET /api/admin/prompt-scenes/{id}`

**作用：** 获取场景详情及该场景下绑定的提示词**条目**（条目含 promptCode、promptName、displayOrder、usageMode），**不包含**提示词正文 content、versionNo、提示词 status。

**请求：**

- 路径：`GET /api/admin/prompt-scenes/{id}`
- 路径参数：`id` = 场景的 **id**（从步骤二列表项里的 `id` 取得）

**响应 `data`：** 单个场景对象，且带 **items**。结构：

| 字段        | 类型   | 说明 |
|-------------|--------|------|
| id          | number | 场景 ID |
| code        | string | 场景编码 |
| name        | string | 场景名称 |
| scope       | string | 作用域 |
| boardCode   | string | 板块编码 |
| roleType    | string | 角色类型 |
| description | string | 描述 |
| status      | string | 场景状态 |
| createdAt   | string | 创建时间 |
| updatedAt   | string | 更新时间 |
| **items**   | array  | 该场景下绑定的提示词条目，见下表 |

**items 中每个元素：**

| 字段         | 类型   | 说明 |
|--------------|--------|------|
| id           | number | 场景项 ID |
| sceneId      | number | 所属场景 ID |
| promptCode   | string | 提示词编码 |
| promptName   | string | 提示词名称（当前生效版本的 name） |
| displayOrder | number | 展示/拼接顺序 |
| usageMode    | string | PREPEND / APPEND / STANDALONE |

**说明：** 条目中只有「当前生效」的提示词会带出名称（后端按 is_active 查的）；**没有** content、versionNo、提示词行级 status（ENABLED/DISABLED）。若需要这些，需再调方式 A 或提示词详情接口，或由后端在某一侧接口里一并返回。

## 四、推荐前端调用流程（如何调用接口）

1. **进入提示词板块**
   - 调用：`GET /api/admin/prompt-scenes`（可按需加 `scope`、`status` 等）。
   - 用返回的 `data` 渲染场景列表（展示 id、code、name、scope、status 等）。

2. **用户点击某一场景**
   - 从该场景项取 **code** 和 **id**。
   - **若要展示「当前生效的提示词列表 + 正文」**  
     → 调用：`GET /api/admin/prompts/scene/{sceneCode}`（用上面的 **code**）。  
     用返回的 `data` 展示：promptCode、versionNo、content、displayOrder、usageMode。
   - **若要展示「场景下的提示词条目 + 名称、顺序、用法」且不强制要正文**  
     → 调用：`GET /api/admin/prompt-scenes/{id}`（用上面的 **id**）。  
     用返回的 `data.items` 展示：promptCode、promptName、displayOrder、usageMode。

3. **若既要「名称 + 正文 + 顺序」**
   - 可先调 `GET /api/admin/prompt-scenes/{id}` 拿 items（含 promptName、displayOrder、usageMode），
   - 再调 `GET /api/admin/prompts/scene/{sceneCode}` 拿 content、versionNo、promptId，
   - 前端按 **promptCode** 合并两条接口数据即可。

4. **预览「实际发给大模型的一段完整文案」**
   - 调用：`GET /api/admin/prompts/scene/{sceneCode}/combined`
   - 响应 `data` 为字符串，即按该场景合并后的完整提示词内容。

---

## 五、当前接口未覆盖的「提示词状态」

- **按场景的提示词列表**（`GET /api/admin/prompts/scene/{sceneCode}`）返回的是供给用 DTO，**没有**提示词行的 **status**（ENABLED/DISABLED）。
- **场景详情的 items**（`GET /api/admin/prompt-scenes/{id}`）也只有 promptCode、promptName、displayOrder、usageMode，**没有**提示词 status。

若前端必须展示「提示词状态」，需要后端在以上某一接口中扩展返回（例如在 `PromptContentDto` 或场景详情的 items 中增加 status/name 等），或前端再按 promptCode 调提示词详情接口（若存在）补全。目前仅靠上述两个接口无法拿到提示词状态。

---

## 六、接口速查

| 步骤           | 方法 | 路径 | 说明 |
|----------------|------|------|------|
| 展示场景列表   | GET  | `/api/admin/prompt-scenes` | 可选 query：scope, boardCode, roleType, status |
| 场景下生效提示词列表（含正文） | GET  | `/api/admin/prompts/scene/{sceneCode}` | 路径用场景 **code** |
| 场景详情（含条目，含提示词名称） | GET  | `/api/admin/prompt-scenes/{id}` | 路径用场景 **id** |
| 合并正文预览   | GET  | `/api/admin/prompts/scene/{sceneCode}/combined` | 整段发给模型的内容 |

以上为「提示词板块」下展示场景列表与当前生效提示词列表的完整调用方式；若后端后续增加 status/name 等字段，只需在对应 data 结构上扩展即可。
